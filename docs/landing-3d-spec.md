## 1. 레퍼런스 분석: matteocourquin.com/en

**관찰 방법.** 헤드리스 Chrome(Playwright, 1440×900)으로 직접 열어 화면·캔버스·네트워크 요청을 확인했고, HTML과 JS 청크를 내려받아 라이브러리 흔적을 확인했다. 프레임 단위 전환 영상, 실제 마우스 호버 모션, 터치 동작은 보지 못했다. 그 항목은 아래에 "추정"으로 표시한다.

### 1-1. 첫 화면과 구조 (관찰)
- 페이지 높이가 뷰포트와 같다(스크롤 없음, `scrollHeight` 900). 전체가 한 장의 "바탕화면"이고, 스크롤 대신 창 열기·접기·드래그로 탐색한다. 스크롤 라이브러리(Lenis) 클래스는 붙어 있지만 이 화면에선 스크롤이 일어나지 않았다.
- 창 8개가 격자 위에 흩어져 있다: 제목 표시줄(검정 바) + 왼쪽 드래그 핸들(점 격자 아이콘) + 오른쪽 `+` 접기/펼치기 버튼. 접힌 것으로 보이는 창(WORK/DETAILS, WORK/IMAGES)은 사선 줄무늬로 표시된다(접힘 상태는 화면으로 추정).
- 중앙에 3D 오브젝트(WebGL2 캔버스 1440×900 전체 크기), 그 뒤에 아주 큰 블랙레터 글자가 있고 창 뒤로 잘린다.
- 상단 도구 모음: 언어, 소리, 3D 오브젝트 교체, 다크/라이트, 레이아웃 초기화, 격자 표시. 하단에 단축키 목록과 시스템 정보(세션 시간, 마우스 속도, FPS, 클릭 수, 뷰포트, 시간대 등)가 낮은 대비의 작은 글자로 깔려 있다.
- 마우스를 따라다니는 십자 커서와 좌표 숫자가 있다.
- 사진 창은 큰 픽셀로 시작해 선명해지는 "픽셀 해제" 연출, 소개 창은 깨진 문자가 읽히는 글자로 풀리는 "스크램블" 연출이다.

### 1-2. 구현 방식 (관찰 + 청크 분석)
| 항목 | 확인 내용 |
|---|---|
| 프레임워크 | Next.js (Turbopack), Sanity CMS 이미지 |
| 3D | three.js 직접 사용(`WebGLRenderer`, `ShaderMaterial`, `GLTFLoader`, `MeshTransmissionMaterial`, `IcosahedronGeometry`), 일부 `@react-three` 흔적 |
| 모델 | `.glb` 6개(heart 273KB, chess 47KB, skull 282KB, jellyfish 529KB, greek 734KB, rose 1.08MB) |
| 모션 | GSAP + ScrollTrigger + SplitText + Flip, 스무스 스크롤 Lenis, 드래그 흔적 |
| 번들 | 가장 큰 청크 1.44MB (gzip 약 408KB). 3D 청크 외에도 460KB(gzip 132KB), 218KB(gzip 70KB) 청크가 있다 |
| 움직임 줄이기 | 스타일시트에서 `prefers-reduced-motion` 규칙을 찾지 못했다(스크립트 쪽 처리는 확인 못 함) |
| 접근성/SEO | 제목 텍스트가 글자마다 두 번씩 들어 있어(`MMAATTTTEEOO`) 스크린리더에서 중복 낭독될 가능성이 있다(추정) |

### 1-3. 우리가 가져오는 것 / 가져오지 않는 것
| 가져온다 (우리 방식으로) | 가져오지 않는다 |
|---|---|
| "한 화면이 곧 바탕화면" 구조, 창 컴포넌트(제목 표시줄·드래그 핸들·접기) | 블랙레터 서체, 보라색+크롬 색감 |
| 창 뒤로 잘리는 배경 큰 글자 | BIOS 문구 그대로 쓰기 |
| 스크램블, 픽셀 해제 | 수상/스택 창, 사운드 |
| 측정 가능한 시스템 정보만 낮은 대비로 | 십자 커서·좌표, 모델 6종 교체, 거대한 번들 |
| 도구 모음 + 단축키 | 가짜 숫자(네트워크 핑 등 측정하지 않는 값) |

우리와 다른 점: 레퍼런스는 3D·모션이 필수고 접근성 처리가 약하다. 우리는 SEO·AdSense 심사 때문에 **텍스트가 항상 DOM에 있고**, 3D·모션을 꺼도 같은 내용이 읽혀야 한다.

## 2. 화면 흐름

```
접속
 └─ [첫 화면] 어두운 격자+노이즈, 3D 하트, "최애를 불러오는 중…" (약 1.4초)
      ├─ 버튼 3개 등장: 처음이신가요? / 바로 다운받기 / 알아보기
      │    호버·포커스 → 하트 두근 + 스파클
      └─ 아무 버튼 클릭
           ↓ (배경이 그대로 이어짐: 격자·노이즈 유지, 하트는 중앙에서 그대로)
      [바탕화면] 배경 큰 글자 → 창들이 150ms 간격으로 차례 등장
           ├─ 눌렀던 버튼의 창은 펼친 채 맨 앞, 나머지 두 창은 접힌 채(제목줄만)
           ├─ 상단 도구 모음 버튼 3개로 창을 다시 열기/앞으로 가져오기
           └─ 도구 모음: 테마(D) · 레이아웃 초기화(L) · 3D 끄기 · 언어(T)
```
- 재방문·`prefers-reduced-motion`·"3D 끄기": 부팅 연출을 건너뛰고 버튼이 바로 보인다.
- 첫 화면의 "알아보기"를 누르지 않아도 창 본문은 모두 DOM에 있다(검색엔진용).

### 2-1. 첫 화면 구성
- 배경: 바탕화면 색 + 48px 격자(가운데가 짙고 가장자리로 옅어지는 마스크) + 노이즈(앱 인트로 `intro-noise-128.png` 재사용, 1초 4프레임 스텝).
- 하트: 앱 인트로와 같은 SVG 하트(검정→아래 흰 그라데이션, 반사광, 림라이트, 노이즈, 눈 2개). 눈은 마우스를 따라가고 하트가 최대 6° 기운다. 마우스가 3초 멈추면 가운데로 돌아온다. 눈 깜빡임 주기 약 4초.
- 문구: "최애를 불러오는 중…" → 로딩 막대(140×3px, 1.3초) → "어디로 갈까요?". BIOS 문구 없음.
- 버튼 3개(높이 44px 이상, 알약): "처음이신가요?"(채움, 이 화면의 유일한 채운 버튼) / "바로 다운받기" / "알아보기"(테두리).
- 호버/포커스/터치: 하트가 1.06배로 360ms 두근, 4점 별 스파클 10개(하트 둘레 + 버튼 쪽 반반), 같은 버튼 400ms 안 재발동 없음. 풀 크기 48개가 동시 상한.
- 배경 큰 글자는 이 화면에선 숨기고 바탕화면 진입 때 나타난다.

### 2-2. 바탕화면 구성 (데스크톱 1024px 이상)
```
[처음이신가요?][바로 다운받기][알아보기]            [테마 D][초기화 L][3D 끄기][KO T]
┌ 처음이신가요? ┐                                   ┌ 다운로드 ┐
│ 3단계           │        ♥ (3D 하트, 중앙)           │ OS 자동 감지 │
└───────────────┘   배경 큰 글자 "최애를 풀어놨습니다"   └──────────┘
┌ 알아보기 ┐          (창 뒤에서 잘림)
│ 기능 · 기록 · 개인정보 │
└────────┘
세션 00:05 · 클릭 3 · 1280×800                    창 제목을 드래그 · Esc로 닫기
```
- 창 기본 위치: 하트(가운데 약 400×300px)를 가리지 않게 좌·우 열에 놓는다. 창 폭 340px(최대).
- 배경 큰 글자: Pretendard 700, `clamp(64px, 15vw, 260px)`, 자간 -0.04em, 대비 아주 낮게(라이트 7%/다크 6% 불투명), 장식이므로 `aria-hidden`. 박다현체·블랙레터 사용 안 함(2026-10-22 지시: 랜딩은 Pretendard만).
- 시스템 정보(좌하단): 세션 시간, 클릭 수, 화면 크기 3가지만. 직접 측정하는 값이라 가짜가 아니다. FPS·핑·마우스 속도·시간대는 넣지 않는다.

### 2-3. 창별 내용
| 창 | 내용 | 비고 |
|---|---|---|
| 처음이신가요? | 3단계 사용법(받기 → 열기 → 고르기) 짧게 | 문구는 copywriter와 확정 필요 |
| 다운로드 | OS 자동 감지. Windows는 `DOWNLOADS.windows`(v1.1.1) 버튼, macOS는 새 버전 전까지 "새 버전은 곧 나와요" 안내. 감지된 OS가 채운 버튼 | 버전·링크는 `constants.ts` 한 곳에서만 |
| 알아보기 | ① 소개 문구(스크램블) ② 기능 ③ 버디 사진 기능 데모(픽셀 해제) ④ 업데이트 기록 ⑤ 개인정보처리방침 요약 + `privacy.html` 링크 | 창 하나에 탭/소제목으로 나눌지는 결정 항목 |
| 업데이트 기록 | 왼쪽 목록, 오른쪽 상세. 선택 상태 하나를 공유 | 아래 4-4 |

## 3. 창 동작 규칙

| 규칙 | 값 |
|---|---|
| 구성 | 제목 표시줄(40px) = 드래그 핸들 + 제목(h2) + 접기(−/+) + 닫기(×) |
| 드래그 | 제목 표시줄만 잡는다(포인터 이벤트, `setPointerCapture`). 본문 선택·스크롤과 충돌 없음 |
| 앞으로 가져오기 | 창 어디든 `pointerdown` → `z-index` 증가 |
| 화면 이탈 제한 | 놓을 때 창이 **최소 48px는 화면 안에 남도록** 보정(좌우 48px, 위 0, 아래 40px). 제목줄이 항상 잡힐 수 있음. 창 크기·창 리사이즈 때도 재보정 |
| 접기/펼치기 | 400ms, 본문 높이만 애니메이션(`grid-template-rows 1fr↔0fr`). **`display:none` 금지**, 본문은 DOM에 남는다. 접힌 본문은 `visibility:hidden`으로 탭 이동과 스크린리더에서 제외 |
| 닫기 | 창을 숨기되(`hidden`) DOM에는 남긴다. 포커스는 연 버튼으로 돌아간다 |
| 열기 | 도구 모음 버튼 또는 첫 화면 버튼. 이미 열려 있으면 앞으로 + 펼침 + 포커스 |
| 레이아웃 초기화 | 위치·접힘·닫힘을 기본값으로(L 또는 버튼) |
| 위치 저장 | 하지 않는다(새로고침하면 기본 배치). 결정 항목 참고 |
| 키보드 | 아래 3-1 |
| 모바일 | 드래그 없음, 세로로 쌓임(5절) |

### 3-1. 키보드와 접근성
- Tab 순서 = DOM 순서: 도구 모음 → 창1(제목줄 → 접기 → 닫기 → 본문) → 창2 …
- 제목줄에 포커스 후 **Alt+방향키**로 24px씩 이동(드래그 대체). 접기/닫기는 버튼이므로 Enter/Space. 창 안에서 **Esc**는 그 창 닫기.
- 업데이트 기록 목록은 `role=tablist`, 위·아래·좌·우 방향키로 이동(선택이 곧 상세 전환).
- 포커스 링: 2px 포인트색, 오프셋 2px(기존 규칙).
- 단축키 D/L/T: `input, textarea, select, [contenteditable]`에 포커스가 있거나 Ctrl/Cmd/Alt가 눌렸으면 무시. 바탕화면 모드에서만 동작. WCAG 2.1.4(한 글자 단축키)를 위해 **단축키 끄기** 스위치를 도구 모음에 둘지는 결정 항목.
- 창은 `section` + `aria-labelledby`(h2). 모달이 아니므로 포커스를 가두지 않는다. 첫 화면 버튼 그룹은 `role=group`.
- 하트 3D는 `role=img` + 설명, 장식 요소(격자·노이즈·큰 글자·스파클)는 `aria-hidden`.

## 4. 모션 값

공통: `transform`/`opacity`만 애니메이션, 이징 `cubic-bezier(0.23, 1, 0.32, 1)`(앱 `--ease-out`).

### 4-1. 시퀀스 (데스크톱)
| 구간 | 시간 | 동작 |
|---|---|---|
| 부팅 | 0–1400ms | 하트·격자·노이즈 표시, 로딩 막대 1.3초 |
| 버튼 등장 | 1400ms~ | opacity 0→1, translateY 10→0, 320ms |
| 하트 두근 | 호버/포커스 | scale 1→1.06→1, 360ms + 스파클 10개(수명 880–1265ms, 이동 66–138px) |
| 진입 | 클릭 후 | 부팅 문구·버튼 페이드 300ms |
| 배경 큰 글자 | +200ms | opacity 0→1, translateY 4%→0, 600ms |
| 창 등장 | +400ms부터 150ms 간격 | opacity 0→1, translateY 14→0, scale .97→1, 360ms |
| 하트 이동 | 진입 | 중앙 위치 46%→50%, 700ms |
| 창 접기/펼치기 | — | 400ms (허용 300–500ms) |
| 테마 전환 | — | 색만 즉시 바뀜(전환 애니메이션 없음) |

### 4-2. 하트 눈 추적
- 눈 최대 이동 12px(하트 160px 기준, 크기에 비례), 가로 대비 세로 62%, 거리가 가까우면 민감, 멀면 최대치 고정.
- 하트 기울임 최대 6°(`perspective 520px`), 반사광은 반대쪽으로 최대 4×3(경로 단위).
- 눈 보간 시상수 60ms, 기울임 90ms. `requestAnimationFrame` 하나로 처리, 탭이 숨겨지면 정지.

### 4-3. 문자 스크램블 / 사진 픽셀 해제
- 스크램블: **600ms**(범위 400–800), 글자 앞에서부터 확정되며 나머지는 무작위 글자. 끝 프레임은 반드시 원문. 소개 문구에만 쓰고 창이 열릴 때 1회. 원문은 **처음부터 DOM에 있는 텍스트를 `data-text`와 `aria-label`로 함께 유지**해 검색엔진·스크린리더는 항상 원문을 읽는다.
- 픽셀 해제: **1000ms**(범위 800–1200), 픽셀 크기 40→20→10→5→2→1 순으로 6단계. 버디 사진 8장을 3.5초마다 순환, 창이 접혔거나 닫혔거나 화면 밖이면 정지. 사진은 1장 ≤150KB webp(기존 규칙), 미리보기에선 Twemoji로 대체.

### 4-4. 업데이트 기록
- 목록과 상세는 하나의 선택 상태(`selectedVersion`)를 공유한다. 목록이 탭, 상세가 탭패널.
- 내용은 `RELEASE_NOTES`(`constants.ts`) 그대로: v1.1.1 · v1.1.0 · v1.0.9 · v1.0.8 · … 요청하신 v1.0.8 / v1.1.1 / v1.2.0 중 **v1.2.0은 아직 출시 전**이라 결정이 필요하다.
- 상세는 선택한 버전 하나만 보이되, 나머지 버전의 텍스트도 DOM에 남긴다(탭패널을 `hidden`으로).

### 4-5. 움직임 줄이기 (`prefers-reduced-motion: reduce`)
- 눈 추적·기울임·스파클·노이즈 애니메이션·스크램블·픽셀 해제·창 이동 애니메이션 전부 끈다. 하트는 정지 이미지(눈은 가운데), 문구는 즉시 원문, 사진은 선명한 상태로 고정.
- 남기는 것은 opacity 전환 ≤150ms뿐. 부팅은 건너뛰고 버튼이 바로 보인다.
- "3D 끄기" 버튼을 누른 상태와 같은 상태다(설정 저장은 `localStorage`, 읽기 실패해도 동작).

## 5. 모바일 대응 (720px 이하)

- 창은 드래그하지 않고 **읽기 순서대로 세로로 쌓는다**: 처음이신가요? → 다운로드 → 알아보기(소개 → 기능 → 사진 → 기록 → 개인정보). 모두 기본 펼침(접기 버튼은 유지).
- 도구 모음은 위에서 줄바꿈 허용(두 줄), 하트는 120px로 줄여 도구 모음 아래에 고정 배치. 눈은 마우스가 없으므로 깜빡임만, 터치하면 그 방향을 한 번 본다.
- 3D(하트)는 SVG라 별도 변환 없이 그대로 쓴다. 호버 없는 기기는 터치 `pointerdown`에 스파클 1회.
- 첫 화면 버튼은 세로 쌓임 또는 줄바꿈, 높이 44px 이상. 가로 스크롤 없음(320/375/414/768px 확인).
- 배경 큰 글자는 모바일에서 숨기거나 2줄로 줄인다(결정 항목 아님, 구현 시 보이는 대로 조정).
- 시스템 정보와 단축키 안내는 숨긴다.

## 6. SEO · 검색엔진/AdSense 대응

- 모든 창 본문은 항상 DOM에 있다: 접힘 = 높이 0 + `visibility:hidden`, 닫힘 = `hidden`, 둘 다 `display`만 다르고 노드는 남는다. 스크램블·픽셀 해제 같은 연출은 DOM 텍스트를 바꾸지 않는다.
- 현재 랜딩은 클라이언트 렌더링(Vite SPA)이고 `index.html`의 `<noscript>`에 요약 본문이 있다. 구조는 그대로 유지한다. 제목은 `h1` 하나(제품명), 창 제목은 `h2`.
- 건드리지 않는 것: 기존 SEO 메타, preview 배포 `noindex`, `privacy.html`, `VITE_SITE_URL` 동작, sitemap.
- 풀어서 읽는 페이지(`about.html`, `faq.html`, `terms.html`, `privacy.html`)는 정적 페이지로 그대로 둔다. 푸터 링크는 바탕화면에서도 접근 가능해야 한다(결정 항목).
- 텍스트가 거의 없는 "큰 글자 + 3D"만 있는 화면으로 보이지 않도록, 창 본문 분량은 지금 랜딩의 본문(기능·설치·업데이트·FAQ)을 줄이지 않는다.

## 7. 3D 구현 방식 비교와 추천

### 7-1. 후보
| | A. SVG/CSS 3D (앱 인트로 방식) | B. three.js (WebGL) | C. 혼합 |
|---|---|---|---|
| 방식 | 하트 SVG + 그라데이션/필터 + CSS `perspective` 기울임 + WAAPI/rAF | 하트를 `ExtrudeGeometry` 또는 `.glb`로 만들고 조명·재질 | 기본 A, 데스크톱에서 B로 업그레이드 |
| 추가 번들(gzip) | **약 3KB** (코드만, 의존성 0) | **약 144KB 실측**(`WebGLRenderer`+메시+조명 최소 구성, three 0.186.1) + 하트 모델을 `.glb`로 쓰면 약 270KB 추가(레퍼런스 heart.glb 기준) | A + 144KB(지연 로드) |
| 첫 화면 영향 | 인라인 SVG, LCP 영향 없음 | 지연 로드해도 하트가 늦게 뜨거나 이중 구현 필요, TBT 증가 | 하트가 A로 즉시 보이고 B는 나중에 교체 |
| 앱과 일치 | **그대로 같은 하트** | 재질 재현에 시간 소요(반사광·림라이트·노이즈) | 일치 후 교체 시 어긋날 수 있음 |
| 모바일/저사양 | 가볍다, 정적 이미지 대체도 쉬움 | WebGL 컨텍스트·배터리 부담, 폴백 필요 | 폴백 = A |
| 움직임 줄이기 | CSS/JS 끄면 그대로 정지 이미지 | 렌더 루프 정지 + 정지 프레임 필요 | A |
| 표현력 | 입체감은 "그럴듯하게", 실제 회전은 ±6° 수준 | 진짜 회전·반사·투과 | B 수준 |
| 구현 난이도 | 낮음(코드 이미 있음) | 중간~높음 | 높음 |

참고 수치(실측, gzip): 현재 랜딩 JS 76.6KB + CSS 5.8KB. A는 이 위에 약 3KB, B는 약 144KB(+모델)가 더해진다. 레퍼런스는 가장 큰 JS 청크만 gzip 약 408KB이고, 그 밖에 460KB·218KB 청크가 더 있다. GSAP/Lenis/SplitText는 필요 없다(WAAPI + rAF + 포인터 이벤트로 충분, 앱 인트로가 이미 그렇게 만들어져 있다).

### 7-2. 추천: **A (SVG/CSS 3D)**, 3D 교체(B)는 승인 후 별도 단계
이유:
1. 앱 인트로와 **같은 하트·같은 눈 추적**이 이미 구현돼 있어 "앱 인트로와 비슷하게"를 가장 정확히 만족한다.
2. 현재 모바일 Lighthouse 성능이 76(LCP 4.2s)로 이미 여유가 없다. 144KB를 더하면 "지금보다 떨어지면 안 된다"를 지키기 어렵다.
3. SVG는 검색엔진·스크린리더·정지 이미지 대체가 쉽다.
4. 나중에 진짜 3D가 필요하면 B를 `import()`로 지연 로드하고 A를 폴백으로 두는 C로 올릴 수 있다. 지금 A로 만들어도 버려지는 코드가 거의 없다.

## 8. 성능 예산

**기준값**(2026-10-22, 현재 `main` 빌드, `vite preview` + Lighthouse CLI, 시뮬레이션 스로틀링):
| | 성능 | 접근성 | 권장사항 | SEO | LCP | TBT | CLS |
|---|---|---|---|---|---|---|---|
| 모바일 | **76** | 100 | 100 | 100 | 4.2s | 370ms | 0 |
| 데스크톱 | **100** | 100 | 100 | 100 | 0.6s | 20ms | 0 |

점수는 실행마다 ±몇 점 흔들리므로 같은 환경에서 3회 중앙값으로 비교한다.

**예산(승인 시 적용)**
| 항목 | 한도 |
|---|---|
| 초기 JS(gzip) | 현재 76.6KB + **15KB 이하**(창·드래그·연출 코드). 3D 라이브러리 0KB |
| 초기 CSS(gzip) | 현재 5.8KB + 4KB 이하 |
| 추가 폰트 | 0개(Pretendard만, 박다현체 제거로 서브셋 하나 줄 수도 있음) |

## 9. 디자인 규칙 예외 (docs 기록 요청 사항)

앱 UI 지시서의 "**네모 안에 네모 금지, 플랫**" 원칙은 유지한다. 단, 아래 두 곳에만 예외를 둔다.

1. **첫 화면 연출**: 3D 하트(그라데이션·반사광·림라이트·노이즈), 격자·노이즈 배경, 스파클, 글로우.
2. **바탕화면 창 연출**: 창의 그림자(blur 허용), 창이 앞으로 올 때의 그림자 강화, 등장 모션, 배경 큰 글자의 낮은 대비 표현.

예외가 아닌 것: **창 안의 본문 읽기 영역은 깔끔한 플랫**(패널 면 + 항목 면 한 단계까지, 그 안에 또 상자 금지). 색은 기존 토큰만 쓰고 보라색·크롬·그라데이션 글자는 쓰지 않는다. 포인트 색 1개 규칙, 채운 버튼은 한 화면에 1개 원칙도 그대로다.
