# 랜딩 "최애가 사는 바탕화면" 설계서 (feature/landing-3d)

상태: **설계안 4차 개정, 승인 전.** 이 문서가 승인되기 전에는 `src/`의 랜딩 코드를 바꾸지 않는다.
임시 미리보기: `_preview/landing-3d.html` (git 제외, 커밋 금지). 브라우저로 열면 다크 인트로 → 줌인 → 라이트 히어로 → 인덱스 → 카테고리 6장을 볼 수 있다. 이전 버전은 `_preview/landing-3d-v3.html`(3차), `landing-3d-v1.html`(1차).
작성 기준일 2026-10-22. 기존 `docs/landing-design-spec.md`(색·간격·버튼 위계)를 바탕으로 하고, 15절의 "디자인 규칙 예외"만 덧붙인다.

## 1. 레퍼런스 분석: matteocourquin.com/en

**관찰 방법.** 헤드리스 Chrome(Playwright, 1440×900)으로 직접 열어 화면·캔버스·네트워크 요청을 확인했고, HTML과 JS 청크를 내려받아 라이브러리 흔적을 확인했다. 프레임 단위 전환 영상, 실제 마우스 호버 모션, 터치 동작은 보지 못했다. 그 항목은 아래에 "추정"으로 표시한다.

### 1-1. 첫 화면과 구조 (관찰)
- 페이지 높이가 뷰포트와 같다(스크롤 없음, `scrollHeight` 900). 전체가 한 장의 "바탕화면"이고, 스크롤 대신 창 열기·접기·드래그로 탐색한다. 스크롤 라이브러리(Lenis) 클래스는 붙어 있지만 이 화면에선 스크롤이 일어나지 않았다.
- 창 8개가 격자 위에 흩어져 있다: 제목 표시줄(검정 바) + 왼쪽 드래그 핸들(점 격자 아이콘) + 오른쪽 `+` 접기/펼치기 버튼. 접힌 것으로 보이는 창(WORK/DETAILS, WORK/IMAGES)은 사선 줄무늬로 표시된다(접힘 상태는 화면으로 추정).
- 중앙에 3D 오브젝트(WebGL2 캔버스 1440×900 전체 크기), 그 뒤에 아주 큰 블랙레터 글자가 있고 창 뒤로 잘린다.
- 상단 도구 모음: 언어, 소리, 3D 오브젝트 교체, 다크/라이트, 레이아웃 초기화, 격자 표시. 하단에 단축키 목록과 시스템 정보(세션 시간, 마우스 속도, FPS, 클릭 수, 뷰포트, 시간대 등)가 낮은 대비의 작은 글자로 깔려 있다.
- 마우스를 따라다니는 십자 커서와 좌표 숫자가 있다.
- 사진 창은 큰 픽셀로 시작해 선명해지는 "픽셀 해제" 연출, 소개 창은 깨진 문자가 읽히는 글자로 풀리는 "스크램블" 연출이다.

### 1-2. 구현 방식 (관찰 + 청크 분석)
| 항목 | 확인 내용 |
|---|---|
| 프레임워크 | Next.js (Turbopack), Sanity CMS 이미지 |
| 3D | three.js 직접 사용(`WebGLRenderer`, `ShaderMaterial`, `GLTFLoader`, `MeshTransmissionMaterial`, `IcosahedronGeometry`), 일부 `@react-three` 흔적 |
| 모델 | `.glb` 6개(heart 273KB, chess 47KB, skull 282KB, jellyfish 529KB, greek 734KB, rose 1.08MB) |
| 모션 | GSAP + ScrollTrigger + SplitText + Flip, 스무스 스크롤 Lenis, 드래그 흔적 |
| 번들 | 가장 큰 청크 1.44MB (gzip 약 408KB). 3D 청크 외에도 460KB(gzip 132KB), 218KB(gzip 70KB) 청크가 있다 |
| 움직임 줄이기 | 스타일시트에서 `prefers-reduced-motion` 규칙을 찾지 못했다(스크립트 쪽 처리는 확인 못 함) |
| 접근성/SEO | 제목 텍스트가 글자마다 두 번씩 들어 있어(`MMAATTTTEEOO`) 스크린리더에서 중복 낭독될 가능성이 있다(추정) |

### 1-3. 우리가 가져오는 것 / 가져오지 않는 것
| 가져온다 (우리 방식으로) | 가져오지 않는다 |
|---|---|
| "한 화면이 곧 바탕화면" 구조, 창 컴포넌트(제목 표시줄·드래그 핸들·접기) | 블랙레터 서체, 보라색+크롬 색감 |
| 창 뒤로 잘리는 배경 큰 글자 | BIOS 문구 그대로 쓰기 |
| 스크램블, 픽셀 해제 | 수상/스택 창, 사운드 |
| 측정 가능한 시스템 정보만 낮은 대비로 | 십자 커서·좌표, 모델 6종 교체, 거대한 번들 |
| 도구 모음 + 단축키 | 가짜 숫자(네트워크 핑 등 측정하지 않는 값) |

우리와 다른 점: 레퍼런스는 3D·모션이 필수고 접근성 처리가 약하다. 우리는 SEO·AdSense 심사 때문에 **텍스트가 항상 DOM에 있고**, 3D·모션을 꺼도 같은 내용이 읽혀야 한다.

## 2. 화면 구성과 흐름

### 2-1. 전체 흐름도

```
접속 ─ 처음 방문(저장값 없음, 직접 링크 없음)
 └─ [0 인트로] 다크 · 3D 하트 · 앱 이름 · 한 줄 문구(2.5초에 읽힘) · (3.0초에) 버튼 2개 · 신뢰 문구 · 스크롤 잠금
      │ 건너뛰기: Esc · "건너뛰기" 버튼 · "본문으로 건너뛰기" 링크 → **빠른 줌인(0.9초)** (스크롤·빈 곳 클릭 없음)
      ├─ "처음이신가요?" ─ 줌인(1.25초, 5절) ─▶ [1 히어로] (메인, 라이트)
      └─ "바로 다운받기" ─ 즉시 이동 ─────────▶ [03 다운로드]
           (OS 자동 감지)  └ 다운로드 창: "3단계 사용법 보기" · "인덱스로"
 재방문 / 직접 링크(#download 등): 인트로·줌인 없이 해당 화면(없으면 히어로)

[1 히어로] 큰 설명 · 라이브 데모 · 핵심 기능 3줄 · 다운로드(가장 큼) · 3단계 사용법 보기
   ▼ 스크롤
[2 인덱스] 가운데 하트 + 노드 6개 + "처음으로"   ── "처음으로" ─ 색 전환(light→dark, 0.9초) ─▶ [0 인트로] 다크, 버튼 즉시 표시, 다시 줌인 가능
   ├─ 노드 클릭(<a href="#id">) / 계속 스크롤(순서대로)
   ▼
[3~8 카테고리] 01 처음이신가요? → 02 기능 → 03 다운로드 → 04 업데이트 기록 → 05 FAQ → 06 개인정보처리방침
   화면마다 진입 연출(6절), 진행 표시 "03 / 06"과 "인덱스로"(아래 가운데)
```
- URL 해시: `#intro #hero #index #start #features #download #updates #faq #privacy`. 줌인·복귀·"바로 다운받기"는 `replaceState`라 **기록이 쌓이지 않고 뒤로 가기 = 사이트 떠남**(사용자 결정, 검증 PASS). 인트로 다시 보기는 "처음으로". 인덱스에서 노드 클릭은 `pushState`.
- 공통 배경(격자·노이즈·큰 글자)은 `position: fixed` 한 장이라 메인 전체가 한 공간으로 이어진다. **인트로만 자기 다크 배경 슬래브**를 가진다(4절). 큰 하트는 화면마다 자리를 옮긴다(인트로 중앙 → 히어로 왼쪽 → 인덱스 중앙 → 카테고리 오른쪽 아래 작게).

### 2-2. 화면 0 · 인트로 (구성)
- 위→아래: 하트(약 190px) → **h1 "최애를 풀어놨습니다"** → 한 줄 문구 → 버튼 2개 → 신뢰 문구. 시간표는 3절.
- 한 줄 문구(최종): **"좋아하는 사진이 모니터 위를 돌아다니는 데스크톱 펫 앱"**. 신뢰 문구: "Windows · macOS(Apple Silicon)" · "무료 · 앱 안 광고 없음".
- 버튼: "처음이신가요?"(테두리, 줌인) / **"바로 다운받기"(채운 버튼, 아래에 Windows v1.1.1 · 무료)**. 테두리는 `#6B6B72`(바탕 대비 3.6:1).
- 인트로 하단 "건너뛰기 · Esc" 버튼은 빠른 줌인이다(스크롤 안내는 제거).
- 도구 모음은 인트로에서 **테마 버튼을 숨긴다**(D 키도 무시). 나머지(초기화·3D·펫·언어)는 유지.

### 2-3. 화면 1 · 히어로 (무슨 앱인지 + 받는 법)
- 왼쪽: 하트 → 소제목 "데스크톱 펫 앱 · Windows / macOS · 무료" → **h2 "최애를 모니터 위에 풀어놓는 데스크톱 펫"** → 설명 2줄 → 버튼 → 신뢰 한 줄(앱 이름, 지원 OS, 무료·광고 없음).
- 버튼: **"바로 다운받기"가 가장 크고 채운 검정(58px)**, "3단계 사용법 보기"(→ `#start`). 둘 다 `<a href>`. "바로 다운받기"는 인트로와 같이 즉시 이동. macOS 접속 시 부제가 "macOS 새 버전 준비 중 · 무료".
- 오른쪽 **라이브 데모**: 하트 버디가 가짜 바탕화면을 걸어 다니고(약 38px/s), 18.5초 주기로 말풍선(앱 실제 멘트) → 점심 알림 카드 → 말풍선 → 퇴근 알림 카드(Twemoji 10개). **"예시 화면 · 실제 앱 동작과 같은 모습" 배지**. 화면 밖·탭 숨김이면 정지, 움직임 줄이기는 정지 화면.
- 데모 아래 **핵심 기능 3가지(상시 노출)**: 사진 한 장이 버디가 돼요 / 시간대에 맞춰 한마디씩 해요 / 점심·퇴근 알림을 챙겨 줘요.
- 데모의 하트는 요청에 따라 "앱의 기본 펫"으로 그렸다. **실제 앱 버디는 내 사진·동물 8종이고 하트는 앱 아이콘**이다(결정 목록 4번).

### 2-4. 화면 2 · 인덱스(마인드맵)
- 가운데 하트, 주변에 노드 6개(번호·제목·한 줄 설명). **노드는 실제 `<a href="#id">`**라서 Tab → Enter로 이동하고 검색엔진이 따라간다. 이동 뒤 포커스는 도착 화면 제목(h2).
- **재정리한 목록과 순서**(좌상 → 우상 → 좌 → 우 → 좌하 → 우하):

| 번호 | 노드 | 한 줄 설명 | 이전 안과의 차이 |
|---|---|---|---|
| 01 | 처음이신가요? | 3단계로 시작해요 | 그대로(첫 번째) |
| 02 | 기능 | 사진 버디 · 말풍선 · 알림 | 4번째 → **2번째** (알아보기에서 합쳐짐) |
| 03 | 다운로드 | Windows v1.1.1 · macOS 준비 중 | 2번째 → **3번째** |
| 04 | 업데이트 기록 | v1.1.1이 최신이에요 | 그대로 |
| 05 | FAQ | 자주 묻는 질문 | 그대로 |
| 06 | 개인정보처리방침 | 수집 정보와 광고 | 그대로 |

- 노드는 최대 7px/6px로 천천히 떠다니고 점선 연결선이 따라간다. 호버/포커스하면 하트가 그 노드를 바라본다.
- **"처음으로" 버튼**(인덱스 제목 아래, `<a href="#intro">`): 누르면 색 전환(5-4)과 함께 인트로로 돌아가며 버튼이 이미 나타나 있어 **다시 줌인을 볼 수 있다**. 상단 로고(`#intro` 링크)도 같다.
- 모바일: 하트 없이 세로 목록.

### 2-5. 화면 3~8 · 카테고리 — 줄글 → 도식·샘플 화면 (4차)

**방식(운영 랜딩에서 가져옴).** 운영 랜딩의 "처음이신가요?" 쪽에는 걸어 다니는 버디 샘플(`BuddyStage`: Twemoji 고양이가 rAF로 걷고 `buddy-bob`·`buddy-jump` 키프레임, 화면 밖이면 IntersectionObserver로 정지)과 앱 3단계 온보딩이 있다. 같은 방식을 쓴다: **가짜 바탕화면 + 하트 버디가 움직이는 가벼운 SVG/CSS 장면**을 `.mini` 컨테이너(`container-type:inline-size`, `cqw` 단위)에 넣고, 실제 이미지·영상은 쓰지 않는다.

**공통 규칙**
- 글자는 이미지가 아니라 **DOM의 진짜 텍스트 노드**다(도식 안 글자도 SVG `<text>`/HTML). 접힌 창도 `hidden`이 아니라 **높이만 접어** 텍스트가 DOM에 남는다(AdSense/검색엔진).
- 장면은 **CSS 키프레임 + SVG 하트**(`heartLite`). 움직임 줄이기는 모두 정지 포스터(`.fc.hold` 규칙을 공유). 화면 밖(`.cat:not(.act)`)·진입 연출 중(`.cat.entering`)엔 일시정지.
- 제목 + 한 줄 + 아이콘 문구가 기본. 긴 설명은 접힌 "자세히" 창에 둔다.

## 3. 인트로 시간표 (4차: 문구 2.5초에 읽힘, 버튼 3.0초, 합계 약 3.3초)

순서 원칙: **하트·앱 이름 → 한 줄 문구 → 버튼**. 문구가 완성되기 전까지 눈 추적·스파클·펫·버튼은 **"조용한 모드"**(하트 눈은 가운데, 버튼은 `inert`). **한 줄 문구는 자동으로 사라지지 않고 줌인 때까지 남고, 버튼은 문구 위가 아니라 아래에 나타나 문구를 가리지 않는다.**

### 3-1. 시간표 (설계값 = `CONFIG.intro`, 실측은 오른쪽)
| 구간(ms) | 요소 | 동작 | 실측(3회, startIntro 기준) |
|---|---|---|---|
| 0–500 | 3D 하트 | 위 24px에서 내려앉으며 나타남 | — |
| 200–700 | 앱 이름(h1) | opacity + translateY 8px → 0 | 시작 641–660ms |
| 400–900 | "최애를 불러오는 중…" + 막대 | 문구 페이드 + 막대 scaleX | — |
| **900–2500** | **한 줄 문구 스크램블** | **1,600ms**, 70ms마다 무작위 글자, 앞에서부터 확정 | — |
| **2500** | **문구 완전히 읽힘** | 원문 확정, 이후 바뀌지 않음 | **2,489 / 2,501 / 2,495ms** |
| 2500 | 조용한 모드 해제 | 눈 추적·커서 자국·지나가는 펫·글자 주변 반짝임 시작(문구가 읽힌 뒤) | — |
| **3000–3300** | **버튼 2개 + 신뢰 문구** | 300ms 페이드(+ translateY 10px). 3000에 `inert` 해제 → 클릭·Tab 가능 | **시작 3,020 / 3,020 / 3,079ms, 완전히 보임 3,185 / 3,189 / 3,246ms, 클릭 가능 3,013–3,023ms** |
| 3300 이후 | 유지 | 문구·버튼 그대로, 줌인 전까지 | — |

- **버튼은 문구가 읽힌 뒤 약 0.5초**에 나타남(요청 0.8초 이내 충족), 합계 **약 3.3초**(요청 ≈3.5초). 문구가 읽히는 2.5초까지 버튼은 없으므로 겹침 없음. 설정으로 `buttonsGap`(0.5초)을 키워 3.5초에 맞출 수 있다.
- **움직임 줄이기**: 스크램블 없음. 하트·이름 opacity만, 문구는 같은 구간(900–2500)에 부드러운 페이드, 버튼은 3.0초에 opacity만, 장식·펫·자국 모두 없음.
- **저장**: `choeae-intro`는 버튼이 나타난 때 영구 저장(`markSeen`). 재방문·직접 링크(`#download` 등)는 인트로를 통째로 건너뜀.

### 3-2. 스크롤 잠금과 건너뛰기 (4차 변경)
- 인트로 구역에서 **스크롤 잠금**(`html[data-zone=intro]`·`body` `overflow:hidden`, 스냅 해제). **스크롤·빈 곳 클릭으로 건너뛰던 것을 없앴다.** 인트로에서 메인으로 가는 길은 **줌인 전환뿐**.
- **건너뛰기 = 빠른 줌인**: Esc / 하단 "건너뛰기" 버튼 / "본문으로 건너뛰기" 링크는 남은 연출을 끝내고(`completeIntro`) **줌인을 900ms로 재생**(`zoomFastMs`)하고 히어로 제목으로 포커스. 그냥 사라지지 않는다. 측정: 도착 약 0.92초, 밝기 변화율 3.13/초.
- 검증(PASS): 휠·PageDown·Space·End·ArrowDown 모두 무반응, 빈 곳 클릭 무반응, Esc·건너뛰기 버튼·링크는 빠른 줌인 후 히어로 도착.

## 4. 인트로는 항상 다크 (색 구역)

### 4-1. 방식: 구역(zone)
- `html[data-zone="intro" | "main"]`. 인트로 구역은 다크 토큰(`#0F0F10` / 패널 `#18181A` / 글자 `#F2F2F2` / 보조 `#8E8E93`)을 쓰고, 메인 구역은 `html[data-theme]`(light 기본)을 따른다. 인트로 화면(`#intro`)에는 같은 다크 토큰을 **직접** 걸어, 스크롤로 인트로와 히어로가 같이 보일 때도 인트로 글자가 뒤집히지 않는다. 인트로는 자기 배경(다크 + 격자 + 노이즈)을 가진 슬래브다.
- **첫 페인트 전에 결정**: `<head>` 인라인 스크립트가 `data-zone`을 정한다. 인트로를 볼 방문자(저장값 없음, 주소가 `#`없음/`#intro`)는 `intro`, 재방문·직접 링크는 처음부터 `main`. 그래서 시스템/저장값이 라이트여도 흰 화면이 깜빡이지 않고, 반대로 직접 링크 방문자에게 어두운 화면이 깜빡이지도 않는다. `<html>` 배경도 토큰을 따른다.
- **측정(첫 페인트)**: 시스템 라이트 + 저장값 light, 시스템 라이트 + 저장값 없음, 시스템 다크 + 저장값 dark 세 경우 모두 첫 화면 휘도 0.09 안팎(다크). 흰 화면(0.9) 없음. 문서 끝 스크립트(`data.js`)를 1.2초 붙잡아 파싱이 늦은 상황에서 재 봄.
- 인트로에서 **D 키·테마 버튼 비활성**(버튼은 `display:none`, D 키는 무시). 메인에서는 동작(검증 PASS).

### 4-2. 저장값별 동작 표 (측정, 8조합)

| 저장된 테마 | 시스템 설정 | 인트로 | 줌인 뒤 메인 |

| 없음(처음 방문) | 라이트 | **다크**(`#0F0F10`, 글자 `#F2F2F2`) | **라이트**(`#F4F4F4`) |
| 없음 | 다크 | **다크** | **라이트**(시스템 무시) |

## 5. 줌인 전환(인트로 → 히어로, 1회) + 색 전환

### 5-1. 시간표 (전체 1,250ms, `CONFIG.zoomMs`)
transform·opacity만 쓴다. 레이아웃을 건드리지 않고, 화면 이동은 오버레이가 덮은 순간에 한 번만 한다.

| 시각(ms) | 동작 | 이징 |
|---|---|---|
| 0 | "처음이신가요?" 클릭 → 잠금막(클릭 차단)·건너뛰기 버튼 표시, 인트로 저장값 기록 | — |
| 0–820 | **하트가 눈 사이로 확대**(`scale 1 → k`, 원점은 하트 중심에서 위로 12.6px) | ease-in `cubic-bezier(.55,0,.85,.4)` |
| 0–300 | 인트로 글자·버튼 사라짐(opacity 1→0, scale 1→1.1) | `cubic-bezier(.4,0,1,1)` |
| **250–870** | **밝기 오버레이 불투명도 0 → 1**(색 = 메인 바탕색) | **사인 곡선 `cubic-bezier(.37,0,.63,1)`, 620ms** |
| ~890 | 오버레이가 완전히 덮인 상태에서 **히어로로 이동**(instant, `pushState('#hero')`, 구역 main) → 한 프레임 쉬고 | — |
| 890–1250 | 오버레이 1 → 0(360ms), 히어로 두 열이 80ms 간격으로 아래서 10px 올라오며 등장(320ms) | `cubic-bezier(.2,.7,.3,1)` |
| 1250 | 잠금 해제, **포커스를 히어로 제목(h2)으로** | — |

- 확대 배율 `k = 1.6 × max(화면 폭·높이) ÷ 하트 크기`, 데스크톱 약 10.8, **모바일(390×844, 하트 .75배) 10.0** — 하트 크기와 화면에 맞춰 자동. 확대가 끝나는 지점에서 하트 몸통이 화면을 덮고 눈이 크게 보이다가 오버레이에 묻힌다.
- **전환 중 클릭 차단**: 투명 잠금막이 최상위(검증 PASS). **Tab은 건너뛰기 버튼에 가둠**. 스크롤 키·휠은 막지 않는다(이동은 어차피 오버레이 뒤에서 절대 위치로 하므로 스크롤해도 결과가 같음).
- **건너뛰기**: Esc / "건너뛰기 · Esc" 버튼. 오버레이가 덜 덮였으면 **120ms 동안만** 서둘러 덮고(색이 갑자기 튀지 않게) 이동한 뒤 200ms에 걷는다. 이미 이동했으면 걷힘만 마무리. 검증: 4배 느린 재생에서 Esc → 1.2초 안에 종료.
- **움직임 줄이기**: 확대 없음. 오버레이 160ms 페이드인 → 이동 → 160ms 페이드아웃(약 0.5초). 검증 PASS(확대 애니메이션 0개).
- 인트로를 이미 본 방문자·직접 링크는 이 전환 없이 해당 화면으로(검증 PASS). 줌인은 이 1곳뿐.

### 5-2. 색 전환 설계 (다크 → 라이트, 번쩍임 방지)
- **방식**: 하트 확대 장면 위에 메인 바탕색(`#F4F4F4`, 저장된 dark면 `#0F0F10`) 오버레이를 **불투명도로 서서히** 올려 밝기를 만든다. 오버레이가 완전히 덮인 순간 구역을 main으로 바꾸므로 토큰 교체가 보이지 않는다. 이후 오버레이가 걷히는 구간은 같은 색 위에서 일어나 **밝기 변화가 없다**(내용만 드러남).
- **램프 길이 620ms, 사인 곡선**: 처음 안(400ms, `cubic-bezier(.4,0,.2,1)`)은 최대 변화율 **5.38/초**(휘도 0.11 → 0.69가 156ms 안에)로 급해서 늘렸다.
- **측정(헤드리스, 느린 재생 4배를 실시간으로 환산, 화면 평균 휘도 0–1):**

| | 시작 | 정점 | 끝 | 최대 변화율 |
|---|---|---|---|---|
| 줌인(다크 → 라이트) | 0.09 | 0.954 | 0.898 | **2.26/초** |
| 복귀(라이트 → 다크) | 0.927 | — | 0.097 | **2.46/초** |
| 처음 안(참고) | 0.09 | 0.956 | 0.90 | 5.38/초 |

  곡선(줌인, ms:휘도): 0:0.09 · 311:0.13 · 453:0.34 · 645:0.76 · 780:0.92 · 895:0.96 · 993:0.92 · 1114:0.91 · 1233:0.90. 단조 증가 후 안착. 정점 0.954에서 끝 0.898로 살짝 내려오는 건 히어로의 격자·노이즈 때문.
- 한계: 휘도는 화면 전체 평균이라 "눈부심"의 체감 지표가 아니다. 일반적인 섬광 기준(1초에 3회 이상)은 해당 없음(한 번의 단조 변화). **실제 모니터 밝기·야간 환경에서의 체감은 확인하지 못했다.**

### 5-3. "처음으로" 복귀(메인 → 인트로, 라이트 → 다크)
| 시각(ms) | 동작 |
|---|---|
| 0 | 클릭 → 잠금막, 인트로 연출이 남아 있으면 즉시 완료(버튼 표시 상태로) |
| 0–600 | 오버레이(인트로 다크색 `#0F0F10`) 0 → 1, 사인 곡선 |

| 600–900 | 오버레이 1 → 0(300ms) → 다크 인트로가 드러남. 포커스는 인트로 제목 |
- 어두워지는 방향이라 부담이 적지만 같은 사인 램프(최대 2.46/초). 인트로엔 버튼이 이미 있고 **"처음이신가요?"로 다시 줌인할 수 있다**(검증 PASS). 움직임 줄이기: 150ms 페이드.
- 스크롤로 직접 올라간 경우(전환 없음): 인트로 슬래브가 위에서 내려오며 다크가 그대로 보이고, 구역 토큰은 화면 중앙선에서 바뀐다.

## 6. 카테고리 진입 연출 (타이틀 중앙 → 제자리 → 창이 하나씩)

### 6-1. 시퀀스 타임라인 (데스크톱, 처음 진입, 실측값 = 애니메이션 타이밍)
기준 시각 0 = 해당 화면이 뷰포트에 **15% 이상** 들어온 순간(IntersectionObserver).

| 시각(ms) | 동작 | 길이 |
|---|---|---|
| 0–150 | 대기(화면이 제자리로 스냅하는 동안, 타이틀은 투명) | 150 |
| **150–500** | **① 타이틀이 화면 중앙에 크게 나타남**(진행 표시 "03 / 06" + 제목, 2.3배, opacity 0→1, 중앙 = 화면 정중앙으로 실측 확인) | 350 |
| 500–800 | 중앙 유지(읽는 시간) | 300 |
| **800–1300** | **② 타이틀이 제자리(왼쪽 위)로 이동**(2.3배 → 1배, translate) | 500 |
| 1100–1320 | 한 줄 안내 문장 페이드인(기능 화면은 스크램블 600ms) | 220 |
| **1000** | **③ 창 1**: 틀 + **제목 표시줄(1000–1161)** 먼저, **본문(1140–1380)** 이어서 | 260 / 161 / 240 |
| 1120 | 창 2: 제목 표시줄 1120–1281, 틀 1120–1380, 본문 1260–1500 | 창 간격 **120ms** |
| 1240 | 창 3: 제목 표시줄 1240–1401, 틀 1240–1500, 본문 1380–1620 | |
| | **전체(창 3개, 기능 화면)** | **1,620ms** |

화면별 총 길이(실측): **기능(창 3개) 1,620ms · FAQ(창 2개) 1,500ms · 업데이트 기록(창 1개) 1,380ms**. 창이 많아도 늘어나지 않도록 창은 틀+제목 표시줄+본문을 한 묶음으로 만들고 **창 단위로만 120ms 간격**을 주었다. 창 안의 아코디언 항목·탭 목록은 개별로 연출하지 않는다(FAQ 11개도 창 하나). 범위 1.2–1.8초 이내.

### 6-2. 모드 (설정값 제안: `CONFIG.revisit`)
| 상황 | 모드 | 동작(실측) | 총 길이 |
|---|---|---|---|
| 처음 진입 | `full` | 위 6-1 | 1.38–1.62초 |
| **같은 방문에서 다시 진입** | `short` (3차 추천, 4차 결정은 아래 `full`) | 타이틀 이동 없음, 창만 200ms 페이드, 60ms 간격 | 320ms(창 3개) |
| 〃 대안 | `none` | 연출 없이 바로 | 0 |
| 〃 **현재 설정(사용자 결정)** | **`full`** | 매번 전체 (중단 안전장치 유지: PageDown·Tab·링크·해시 이동으로 즉시 끝남) | 1.62초 |
| 직접 링크(#faq 등) | `direct` | **타이틀 중앙 연출 생략**. 타이틀 200ms 페이드, 창은 80ms 후 100ms 간격(틀+제목 표시줄 → 본문) | 560ms(창 2개) |
| 움직임 줄이기 | `rm` | **이동 없음.** 타이틀·안내·창이 한꺼번에 150ms 페이드 | 150ms |
| 모바일(≤720px) | `mobile` | 타이틀 1.5배, 중앙 약 100–300ms·유지 약 120ms·이동 420–700ms, 창은 520ms부터 **80ms 간격**, 거리 줄임 | **960ms**(창 3개, 약 1초) |
- **`full` 매번 재생에 대한 의견**: 처음 한 번은 화면의 정체를 알려 주지만, 인덱스에서 여러 화면을 오가거나 되돌아올 때마다 타이틀이 중앙에 1.4~1.6초 머무는 구간이 반복되어 **느리고 지루하게 느껴질 가능성**이 크다(특히 다운로드를 다시 확인하러 올 때). 완화책: ① 이미 중단 안전장치가 있어 막히지는 않음 ② 같은 화면 재진입만 `short`(0.32초)로 하고 새 화면은 `full` ③ 한 방문에서 3회 넘으면 `short`. 실기기로 반복 체감은 확인하지 못했다. 지시대로 `full`을 유지하고 `CONFIG.revisit` 한 줄로 바꿀 수 있게 해 두었다.
- "같은 방문"의 기준은 페이지를 열어 둔 동안(메모리). 화면이 **완전히 뷰포트를 벗어났다가** 돌아와야 다시 재생된다(지나가며 빠져나가는 중에 다시 시작되지 않음 — 측정 중 잡은 버그, 아래).

### 6-3. 중단 규칙 (연출이 사용자를 막으면 안 됨)
다음이 일어나면 **즉시 마지막 상태로 건너뛴다**(애니메이션 `finish()`): PageDown/PageUp/Home/End/Space/방향키, **Tab**, 모든 `pointerdown`(클릭), 인덱스 링크·해시 이동·`popstate`(뒤로/앞으로), **화면에서 멀어지는 스크롤**(해당 화면 위치가 가장 가까웠던 때보다 뷰포트의 15% 넘게 멀어짐 — `scroll` 이벤트만 사용, `wheel` 리스너 없음), 화면이 뷰포트를 완전히 벗어남. 도착(가까워지는) 스크롤은 허용한다.

**검증 (7개 상황 모두 PASS, 중단 후 해당 화면 연출 0개·모든 요소가 투명도/변형 없는 자연 상태·콘솔 오류 없음):**
PageDown · Tab 키 · 인덱스로 링크 클릭 · 해시 이동(`location.hash`) · 계속 스크롤(큰 휠, 창 밖 위치) · 창 클릭 · (뒤로 가기는 사이트를 떠남 — 기록이 없음).

### 6-4. 점진적 향상 (JS가 실패해도 읽힘)
- 모든 텍스트가 **처음부터 DOM에** 있고 `display:none` / `visibility:hidden` / `opacity:0`으로 숨기지 않는다(연출 전 상태에서 모든 카테고리 제목·안내·창·제목 표시줄·본문 검사 → 숨은 것 0개, PASS).
- 시작 상태는 CSS가 아니라 **Web Animations의 `fill:'backwards'`**(opacity/transform)로만 만든다. 애니메이션이 만들어지기 전·JS가 느리거나 실패하면 자연 상태(보임)로 남는다. **JS를 전부 차단**해도 인트로 이름·문구·버튼과 카테고리 제목 6개가 읽힌다(PASS).
- 인트로의 숨김(버튼 등)도 같은 방식이며 `inert`는 JS가 건다(실패하면 걸리지 않음).

### 6-5. 접근성
- 인덱스 링크 Enter(또는 해시 이동·뒤로 가기)로 도착하면 **포커스가 화면 제목(h2)으로** 이동(검증 PASS). 줌인 뒤에는 히어로 제목, "처음으로" 뒤에는 인트로 제목.
- **스크린리더 읽는 순서 = DOM 순서**(접근성 트리로 확인): "02 / 06" → 제목(h2) → 안내 문장 → 창1(h3, 접기·닫기 버튼, 본문) → 창2 … 시각 순서(타이틀이 중앙에서 이동)와 무관하게 일정. 진행 표시 `aria-live`는 제거(이동마다 읽히지 않게).
- 움직임 줄이기: 이동 없는 150ms 페이드. 전환 중 키보드 사용자는 Tab이 건너뛰기 버튼에 가둬지고 Esc로 끝낼 수 있다.
- 한계: 실제 스크린리더(NVDA·VoiceOver) 낭독은 확인하지 못했다(접근성 트리만 확인).

### 6-6. 측정 (진입 연출)
| | 평균 fps | 최대 프레임 간격 | 33ms 초과 | CLS |
|---|---|---|---|---|
| CPU 1배 | 60.0 | 17ms | 0 / 147 | **0** |
| CPU 4배 느리게 | 59.2 | 33ms | 0 / 148 | **0** |
- **잡은 버그 2개(이번 작업 중)**: ① 부드러운 스크롤로 도착하는 중에 "계속 스크롤"로 오인해 연출이 끝난 뒤, 빠져나가는 이전 화면이 임계값을 다시 넘으며 새 연출을 시작해 도착 화면 연출을 끊었다 → 한 번 지난 화면은 완전히 벗어날 때까지 "결정됨"으로 기록. ② 타이틀 애니메이션 전체에 ease-out을 걸어 시간축이 왜곡돼 중앙에 안 머물렀다 → 효과 전체는 `linear`, 구간 이징만 키프레임에.

## 7. 창 동작 규칙 (카테고리 화면 안)

| 키보드 | 제목줄에 포커스 후 **Alt+방향키**로 24px씩 이동(검증 PASS), 접기/닫기는 버튼(Enter), 창 안에서 **Esc = 닫기**(검증 PASS) |
| 단축키 | D 테마 / L 초기화 / T 언어. 입력창·Ctrl·Alt·Cmd 중이면 무시(검증 PASS). 단축키 끄기 스위치는 결정 항목 |

## 13. 스크롤 하이재킹 없이 가능한가 + SEO/접근성 영향

### 13-1. 하이재킹 없음 (코드 점검 + 동작 확인)
- `wheel`·`touchmove`·`touchstart` 리스너 **0개**. 스크롤은 브라우저 기본이고 `scroll` 리스너는 passive로 상태만 읽는다.
- `preventDefault()`는 7곳이며 **스크롤과 무관**: 링크 클릭을 줌인/즉시 이동/인트로 복귀로 대체(3곳), Alt+방향키 창 이동, 탭 목록 방향키, **줌인 중 Tab 포커스 가둠**, 막아 둔 미리보기 다운로드 링크.
- 사용한 것: CSS `scroll-snap-type: y proximity`(+ `scroll-snap-align`), `IntersectionObserver`(화면 중앙선 활성 / 15% 진입 감지), `history.replaceState/pushState`, 앵커 `href="#id"`.
- **줌인은 인트로 → 메인 1회뿐**이고, 인덱스·카테고리 이동은 스크롤·앵커다. **인트로 동안만 스크롤을 잠근다**(`html`과 `body` 모두 `overflow:hidden`+스냅 해제; `html`만으로는 키보드 스크롤이 샜음. 휠·PageDown·Space·End·방향키 모두 막힘 확인). 줌인 이동은 오버레이 뒤에서 절대 위치로 한다. 스크롤바 자리 어두운 띠는 인트로 구역이 다크 슬래브라 보이지 않음.
- 키보드 스크롤이 스냅과 맞게 동작(PageDown/Space/End/Home), 해시 이동·뒤로·앞으로·직접 링크 PASS.
- **한계 1**: `proximity`로 바꿔 작은 휠 입력이 되돌아가는 문제를 없앴다(결정 16-1의 5). 실제 휠·트랙패드 감각은 실기기로 확인하지 못했다. **한계 2**: 화면이 뷰포트보다 키가 크면 스냅이 아래를 가릴 수 있어 540px 이하는 스냅을 끔.

### 13-2. SEO 영향
- 모든 텍스트가 **DOM에 소스 순서대로**(인트로 → 히어로 → 인덱스 → 카테고리 6개). h1은 인트로에 하나, 화면마다 h2, 창은 h3, 인덱스 노드는 실제 링크. 연출은 DOM 텍스트를 바꾸지 않는다(스크램블은 인트로 문구와 기능 안내 문장 두 곳뿐이고 **끝 상태 = 원문**, 초기 DOM 원문은 처음부터 최종 문구).
- 접힘은 높이 0 + `visibility:hidden`, 닫힘은 `hidden`으로 **노드는 항상 존재**. 숨은 텍스트는 가중치가 낮아질 **가능성**이 있어 중요한 본문(기능·FAQ·다운로드)은 기본 펼침 전제. 측정하지 못함.
- 해시는 별도 URL로 색인되지 않는다(한 URL `/`에 모든 내용). 정적 페이지(`about/faq/terms/privacy.html`)는 그대로. 현재 랜딩과 같은 클라이언트 렌더링(Vite SPA)이라 `<noscript>` 요약·JS 렌더링 크롤러에 의존. 인트로 h1·문구는 **JS 없이도 최종 상태로 읽힘**(검증 PASS).
- 기존 SEO 메타·noindex(프리뷰)·`privacy.html`·`VITE_SITE_URL`은 건드리지 않는다. Lighthouse SEO는 미리보기가 `noindex`라 의미 없음.

### 13-3. 접근성 영향
- 통과: 포커스 링, Tab 순서, Enter로 인덱스 이동 후 제목 포커스, 창 키보드 조작, 입력창 단축키 무시, 움직임 줄이기, 인트로 대비(4-3), 전환 중 포커스 관리, Lighthouse 접근성 100.
- 주의: ① 인트로 버튼은 3.0초 전까지 `inert`(Esc·"건너뛰기"·"본문으로 건너뛰기"는 빠른 줌인으로 즉시 진행). ② **건너뛰기 링크(본문으로)**와 **단축키 끄기 스위치**는 4차에 추가. ③ 스크린리더 실제 낭독은 미확인.

### 16-3. 새로 생긴 질문
1. **"바로 다운받기"는 줌인 없이 즉시 이동**이라 "인트로에서 메인으로 가는 유일한 길은 줌인"과 부딪힌다. 지금은 **다운로드로 바로 이동(0.3초 안)**을 유지했다. "무조건 줌인을 거친다"로 바꾸면 줌인 → 히어로 → 다운로드로 가야 해서 첫 방문자의 '바로'가 느려진다. 어느 쪽이 맞는지.
2. **카테고리 재진입 `full` 매번**: 의견은 6-2. `short`로 바꾸는 게 좋다고 보지만 지시대로 `full`로 두었다. 일정 횟수(예: 한 방문 3회) 뒤 `short` 전환 옵션을 둘지.
3. **창 접힘 기본값**: 시작 화면 "자세한 설치 단계"와 기능 화면 "더 알아보기"는 접힌 채 DOM에 텍스트가 있다. 처음부터 펼치는 편이 나은 화면이 있는지(캡처로 판단).
4. **실제 앱 화면 캡처 5장 vs 도식**: 지금 기능 카드는 가벼운 SVG/CSS 도식이다. 앱 실제 캡처(이미지)를 쓰면 정확하지만 용량·AdSense 텍스트 비중이 불리하다. 도식 유지가 추천.
5. **이전부터 이어지는 것**: 개인정보 요약 문구·시행일 확정, 박다현체 로고 교체, 구현 시작 조건(승인 후).
