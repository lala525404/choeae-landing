# 랜딩 "최애가 사는 바탕화면" 설계서 (feature/landing-3d)

상태: **설계안 2차 개정, 승인 전.** 이 문서가 승인되기 전에는 `src/`의 랜딩 코드를 바꾸지 않는다.
임시 미리보기: `_preview/landing-3d.html` (git 제외, 커밋 금지). 브라우저로 열면 인트로 → 히어로 → 인덱스 → 카테고리 6장을 스크롤로 볼 수 있다.
작성 기준일 2026-10-22. 기존 `docs/landing-design-spec.md`(색·간격·버튼 위계)를 바탕으로 하고, 12절의 "디자인 규칙 예외"만 덧붙인다.
**이 문서의 숫자 중 "측정"이라고 적은 것만 실측이고, 나머지는 설계 값이다. 못 확인한 것은 각 절에 "한계"로 적었다.**

## 1. 레퍼런스 분석: matteocourquin.com/en

**관찰 방법.** 헤드리스 Chrome(Playwright, 1440×900)으로 직접 열어 화면·캔버스·네트워크 요청을 확인했고, HTML과 JS 청크를 내려받아 라이브러리 흔적을 확인했다. 프레임 단위 전환 영상, 실제 마우스 호버 모션, 터치 동작은 보지 못했다. 그 항목은 아래에 "추정"으로 표시한다.

### 1-1. 첫 화면과 구조 (관찰)
- 페이지 높이가 뷰포트와 같다(스크롤 없음, `scrollHeight` 900). 전체가 한 장의 "바탕화면"이고, 스크롤 대신 창 열기·접기·드래그로 탐색한다. 스크롤 라이브러리(Lenis) 클래스는 붙어 있지만 이 화면에선 스크롤이 일어나지 않았다.
- 창 8개가 격자 위에 흩어져 있다: 제목 표시줄(검정 바) + 왼쪽 드래그 핸들(점 격자 아이콘) + 오른쪽 `+` 접기/펼치기 버튼. 접힌 것으로 보이는 창(WORK/DETAILS, WORK/IMAGES)은 사선 줄무늬로 표시된다(접힘 상태는 화면으로 추정).
- 중앙에 3D 오브젝트(WebGL2 캔버스 1440×900 전체 크기), 그 뒤에 아주 큰 블랙레터 글자가 있고 창 뒤로 잘린다.
- 상단 도구 모음: 언어, 소리, 3D 오브젝트 교체, 다크/라이트, 레이아웃 초기화, 격자 표시. 하단에 단축키 목록과 시스템 정보(세션 시간, 마우스 속도, FPS, 클릭 수, 뷰포트, 시간대 등)가 낮은 대비의 작은 글자로 깔려 있다.
- 마우스를 따라다니는 십자 커서와 좌표 숫자가 있다.
- 사진 창은 큰 픽셀로 시작해 선명해지는 "픽셀 해제" 연출, 소개 창은 깨진 문자가 읽히는 글자로 풀리는 "스크램블" 연출이다.

### 1-2. 구현 방식 (관찰 + 청크 분석)
| 항목 | 확인 내용 |
|---|---|
| 프레임워크 | Next.js (Turbopack), Sanity CMS 이미지 |
| 3D | three.js 직접 사용(`WebGLRenderer`, `ShaderMaterial`, `GLTFLoader`, `MeshTransmissionMaterial`, `IcosahedronGeometry`), 일부 `@react-three` 흔적 |
| 모델 | `.glb` 6개(heart 273KB, chess 47KB, skull 282KB, jellyfish 529KB, greek 734KB, rose 1.08MB) |
| 모션 | GSAP + ScrollTrigger + SplitText + Flip, 스무스 스크롤 Lenis, 드래그 흔적 |
| 번들 | 가장 큰 청크 1.44MB (gzip 약 408KB). 3D 청크 외에도 460KB(gzip 132KB), 218KB(gzip 70KB) 청크가 있다 |
| 움직임 줄이기 | 스타일시트에서 `prefers-reduced-motion` 규칙을 찾지 못했다(스크립트 쪽 처리는 확인 못 함) |
| 접근성/SEO | 제목 텍스트가 글자마다 두 번씩 들어 있어(`MMAATTTTEEOO`) 스크린리더에서 중복 낭독될 가능성이 있다(추정) |

### 1-3. 우리가 가져오는 것 / 가져오지 않는 것
| 가져온다 (우리 방식으로) | 가져오지 않는다 |
|---|---|
| "한 화면이 곧 바탕화면" 구조, 창 컴포넌트(제목 표시줄·드래그 핸들·접기) | 블랙레터 서체, 보라색+크롬 색감 |
| 창 뒤로 잘리는 배경 큰 글자 | BIOS 문구 그대로 쓰기 |
| 스크램블, 픽셀 해제 | 수상/스택 창, 사운드 |
| 측정 가능한 시스템 정보만 낮은 대비로 | 십자 커서·좌표, 모델 6종 교체, 거대한 번들 |
| 도구 모음 + 단축키 | 가짜 숫자(네트워크 핑 등 측정하지 않는 값) |

우리와 다른 점: 레퍼런스는 3D·모션이 필수고 접근성 처리가 약하다. 우리는 SEO·AdSense 심사 때문에 **텍스트가 항상 DOM에 있고**, 3D·모션을 꺼도 같은 내용이 읽혀야 한다.

## 2. 화면 구성과 흐름 (2차 개정: 인트로 → 히어로 → 인덱스 → 카테고리)

### 2-0. 이번 개정에서 바뀐 결정과 이유

| # | 바뀐 결정 | 이유 |
|---|---|---|
| 1 | **스파클은 커서가 아니라 "펫 주변"에서 가끔** 나온다. 펫을 끄면 커서에서 나온다 | 커서 트레일과 따라다니는 펫이 둘 다 움직이면 지저분해진다. 역할을 나눠 펫 = 동행, 스파클 = 펫이 움직일 때 흩날리는 먼지 |
| 2 | 첫 화면(인트로)에 **한 줄 설명 + 지원 OS + 무료**를 넣고, 바로 다음 **히어로**에 라이브 데모와 핵심 기능 3가지를 상시 노출 | 스크롤형일 때의 "이게 뭔지 바로 보임"이 사라졌다는 피드백. 5초 테스트 기준으로 검토(4절) |
| 3 | **라이트가 기본.** 저장된 선택(`choeae-theme`)만 따르고 시스템 설정은 따르지 않는다 | 요청. 검증: 시스템 다크 + 저장값 없음 → 라이트, 저장값 `dark` → 다크, 저장값 `system`일 때만 시스템을 따름 |
| 4 | 3D 느낌을 강화하고 **"3D 끄기" = 완전 플랫 하트**로 바꿈 | 이전엔 끄기가 눈·기울임만 꺼서 차이가 안 보였다(8절 원인 분석) |
| 5 | 구조를 **스크롤형(히어로 → 인덱스 마인드맵 → 카테고리 6장)**으로 바꾸고 창은 각 카테고리 화면 안에서 쓴다 | 요청. 스크롤 하이재킹 없이 CSS scroll-snap + IntersectionObserver로만 구현(10절) |
| 6 | 작은 하트 **펫이 커서를 따라다닌다**(터치·움직임 줄이기에선 고정 마스코트) | 요청. 끄는 스위치를 도구 모음에 둠 |
| 7 | **인트로를 맨 앞에 복원**하고 인트로 다음에 히어로가 온다 | 요청("인트로 화면 넣어놓고 지금 히어로가 오는 게 좋겠다") |
| 8 | **창 내용을 지난 스크롤형 랜딩의 실제 문구·데이터로 채움** | 요청("페이지당 설명이 친절하지 않다"). `constants.ts`(설치 단계·기능·업데이트 기록·FAQ·사진 팁)와 앱 화면 캡처 5장을 그대로 사용 |
| 9 | **박다현체를 쓰지 않는다**(Pretendard만) | 2026-10-22 지시. 큰 글자도 Pretendard 700 |

### 2-1. 전체 흐름도

```
접속 ─▶ [0 인트로] 3D 하트 · 앱 이름 · 한 줄 설명 · OS/무료 · 버튼 3개
          │  "처음이신가요?" → #start     "바로 다운받기" → #download     "알아보기" → #hero
          │  (또는 그냥 스크롤)
          ▼
        [1 히어로] 큰 설명 · 라이브 데모(하트 버디) · 핵심 기능 3줄 · 다운로드 버튼(가장 큼)
          ▼ 스크롤 / "알아보기"
        [2 인덱스] 가운데 하트 + 마인드맵 노드 6개 (호버하면 하트가 그 노드를 봄)
          ├─ 노드 클릭(<a href="#id">) → 해당 카테고리로 부드럽게 이동 + 창 열림 연출
          └─ 클릭 없이 계속 스크롤하면 인덱스에 적힌 순서대로 이어짐
        [3~8 카테고리]  01 처음이신가요? → 02 다운로드 → 03 기능 → 04 업데이트 기록 → 05 FAQ → 06 개인정보처리방침
          │  화면 하나 = 100svh 한 장(scroll-snap), 창 드래그·접기 유지
          │  진행 표시 "03 / 06"(아래 가운데) + "인덱스로" 버튼 → #index 로 복귀
          ▼
        (끝) 06 에서 더 내려갈 곳 없음. "인덱스로" 또는 상단 로고(#intro)로 복귀
```
- URL 해시: `#intro #hero #index #start #download #features #updates #faq #privacy`. 클릭한 앵커는 브라우저 기본 방식으로 기록이 쌓이고, 스크롤로 바뀐 위치는 `replaceState`로 덮어써서 기록이 쌓이지 않는다.
- 직접 링크(`…#faq`)로 들어오면 부팅을 건너뛰고 해당 화면이 바로 보인다(검증 PASS, 아래 10절).
- 공통 배경(격자·노이즈·큰 글자)은 `position: fixed` 한 장이라 모든 화면이 한 공간으로 이어진다. 큰 하트는 화면마다 자리를 옮겨 다닌다(인트로 중앙 → 히어로 왼쪽 → 인덱스 중앙 → 카테고리 오른쪽 아래 작게, 0.85초).

### 2-2. 화면 0 · 인트로
- 구성(위→아래): 하트(약 190px, 눈이 커서를 따라감) → **h1 "최애를 풀어놨습니다"** → 한 줄 설명 → 버튼 3개 → 한 줄 신뢰 문구.
- 한 줄 설명(최종): **"좋아하는 사진이 모니터 위를 돌아다니는 데스크톱 펫 앱"**. 처음 1.4초만 "최애를 불러오는 중…" + 로딩 막대(140×3px)가 보이고, 그 뒤 설명으로 풀린다(스크램블 500ms, 끝은 항상 읽히는 원문). DOM 원문은 처음부터 최종 문구다.
- 신뢰 문구: "Windows · macOS(Apple Silicon)" · "무료 · 앱 안 광고 없음".
- 버튼: "처음이신가요?" / **"바로 다운받기"(채운 버튼, 아래에 Windows v1.1.1 · 무료)** / "알아보기". 호버·포커스 시 하트가 버튼 쪽을 바라보고 두근(1.07배, 360ms) + 스파클 10개.
- 직접 링크·움직임 줄이기·이미 스크롤한 상태로 들어오면 부팅을 건너뛴다. 아래쪽 "스크롤하면 소개"는 `#hero` 링크.
- 배경 큰 글자는 인트로에서 숨기고 다음 화면부터 보인다(0.6초 페이드).

### 2-3. 화면 1 · 히어로 (무슨 앱인지 + 받는 법)
- 왼쪽: 하트 → 소제목 "데스크톱 펫 앱 · Windows / macOS · 무료" → **h2 "최애를 모니터 위에 풀어놓는 데스크톱 펫"** → 설명 2줄("좋아하는 사진이 버디가 되어 내 화면 위를 돌아다녀요. 점심·퇴근 시간엔 알림도 챙겨 줘요.") → 버튼 → 신뢰 한 줄(앱 이름, 지원 OS, 무료·광고 없음).
- 버튼 위계: **"바로 다운받기"가 가장 크고 채운 검정(58px, 18px 글자, 그림자)**, "처음이신가요?"·"알아보기"는 48px 테두리 버튼. 채운 버튼은 한 화면에 1개. macOS 접속 시 부제가 "macOS 새 버전 준비 중 · 무료"로 바뀐다.
- 오른쪽 **라이브 데모**(창을 열지 않아도 보임):
  - 가짜 바탕화면(작업 창 모양 + 작업 표시줄)에서 **하트 버디가 좌우로 걸어 다닌다**(약 38px/s, 가장자리에서 방향 전환, 걸음 bob 4px).
  - 약 18.5초 주기: 말풍선(1.2초) → **점심 알림 카드**(5.2초) → 말풍선(10초) → **퇴근 알림 카드**(13.5초). 말풍선 문구는 앱의 실제 시간대별 멘트("오늘 점심은 뭐예요?", "물 마셨어요?", "조금만 더 하면 퇴근!", "허리 펴요!", "퇴근까지 얼마 안 남았어요!"). 알림 카드는 앱 퇴근 알림과 같은 구성(버디 + "오후 6:00 퇴근 시간이에요" + Twemoji 이모지 10개가 아래에서 위로).
  - **"예시 화면 · 실제 앱 동작과 같은 모습" 배지**를 항상 단다. 화면 밖·탭이 숨겨지면 정지, 움직임 줄이기에서는 말풍선이 떠 있는 정지 화면.
- 데모 아래 **핵심 기능 3가지(상시 노출)**: ① 사진 한 장이 버디가 돼요 ② 시간대에 맞춰 한마디씩 해요 ③ 점심·퇴근 알림을 챙겨 줘요.
- 데모의 하트는 요청에 따라 "앱의 기본 펫"으로 그렸다. 다만 **실제 앱의 버디는 내 사진이나 동물 8종이고 하트는 앱 아이콘**이다. 이 차이는 결정 목록 3번.

### 2-4. 화면 2 · 인덱스(마인드맵)
- 가운데 하트(1.12배), 주변에 노드 6개: 01 처음이신가요? / 02 다운로드 / 03 기능 / 04 업데이트 기록 / 05 FAQ / 06 개인정보처리방침. 노드마다 번호, 제목, 한 줄 설명.
- **노드는 실제 `<a href="#id">`**라서 Tab → Enter로 이동하고 검색엔진이 따라갈 수 있다. 이동 뒤 포커스는 도착 화면의 제목(h2)으로 간다(검증 PASS).
- 노드는 최대 7px/6px 범위로 서로 다른 위상으로 천천히 떠다니고(주기 약 10초) 점선 연결선이 따라간다. **호버/포커스하면 하트가 그 노드를 바라보고 연결선이 실선·진하게** 바뀐다.
- 모바일(720px 이하): 하트 없이 **세로 목록**(번호·제목·설명 카드)으로 단순화.

### 2-5. 화면 3~8 · 카테고리 (창 내용은 지난 스크롤형 랜딩의 실제 문구)

| 화면 | 창 | 내용(출처) |
|---|---|---|
| 01 처음이신가요? | 설치는 금방 끝나요 | Windows/macOS 탭(접속 OS가 먼저 열림), 단계별 설명(`WINDOWS_STEPS`/`MAC_STEPS`) |

## 3. 창 동작 규칙 (카테고리 화면 안)

| 규칙 | 값 |

| 구성 | 제목 표시줄(42px) = 드래그 핸들 + 제목(h3) + 접기(−/+) + 닫기(×) |

## 4. 5초 테스트: 첫 화면만 보고 알 수 있는 정보

기준: 처음 방문한 사람이 5초 안에 **"이게 뭐고 어떻게 받는지"** 알 수 있는가. 아래는 설계자가 화면(캡처 `first-intro-light.png`, `first-hero-light.png`)을 보고 읽어낸 것이며, **실제 사용자 테스트는 하지 않았다.**

**① 인트로(첫 화면)만 봤을 때 — 통과**
- 알 수 있음: 앱 이름 "최애를 풀어놨습니다", **데스크톱 펫 앱**이라는 종류, "좋아하는 사진이 모니터 위를 돌아다닌다"는 한 줄 개념, **Windows · macOS(Apple Silicon)**, **무료 · 광고 없음**, **"바로 다운받기" 버튼이 가장 눈에 띔(Windows v1.1.1)**, 처음이면 "처음이신가요?"로 3단계 사용법.
- 모름: 실제로 어떻게 생겼고 어떻게 움직이는지(데모), 핵심 기능 3가지 → 스크롤 한 번이면 히어로에서 해결.
- 이전 안(인트로 문구가 "어디로 갈까요?"뿐)은 **"무슨 앱인지 모름"으로 실패**했다. 그래서 설명·OS·무료를 인트로에 넣었다.

**② 히어로만 봤을 때 — 통과**
- 알 수 있음: 위 정보 + 하트 버디가 가짜 바탕화면을 걸어 다니며 **말풍선**("오늘 점심은 뭐예요?")과 **점심·퇴근 알림 카드**가 뜨는 모습(예시 배지 있음), 핵심 기능 3가지, 앱 이름·OS·무료.
- 한계: 데모에서 알림 카드는 약 5초 뒤에 처음 나온다(5초 안에 못 볼 수 있음). 말풍선은 1.2초에 먼저 뜬다.

### 8-4. 그래도 부족하면: three.js를 데스크톱에서만 지연 로드 — 숫자 비교

비교 방식: 미리보기에 `?three=1`을 붙이면 **데스크톱·움직임 줄이기 아님·터치 아님**일 때만 `load` 이후 유휴 시간에 three.js 청크를 `import()`로 받아 `MeshPhysicalMaterial`(clearcoat) + 환경맵(`RoomEnvironment`) + `ExtrudeGeometry` 하트를 렌더하게 했다(화면에는 쓰지 않고 비용만 측정). Lighthouse CLI 3회 중앙값, `python -m http.server`(무압축 서빙).

| | A. SVG/CSS(현재 안) | B. + three.js 지연 로드(데스크톱만) |
|---|---|---|
| 추가 JS(gzip) | 0KB(코드는 미리보기 전체 HTML이 gzip 약 24KB) | **약 145KB**(원본 575KB; 최소 구성만이면 144KB) |
| 전송량(무압축 측정) | 154KB | 716KB(+562KB) |
| 데스크톱 성능 점수 | 100 | **72** |
| 데스크톱 TBT | 0ms | **873ms** |
| 데스크톱 LCP / CLS | 0.44s / 0.03(당시) | 0.44s / 동일 — **LCP는 지연 로드라 변화 없음** |
| 모바일 | 97(당시) | 97 — **모바일에는 로드하지 않아 변화 없음**(TBT 10→40ms는 측정 오차 범위) |
| 폴백 | 필요 없음(기본) | 모바일·움직임 줄이기·WebGL 실패 시 A로 폴백 필요 |

- **추천: A 유지.** 강화 후 입체감이 이전보다 분명하고, B는 데스크톱 Lighthouse 성능을 100 → 72로 떨어뜨려 "점수가 지금보다 떨어지면 안 된다"를 어긴다(지연 로드해도 파싱·실행이 TBT로 잡힘).

## 10. 스크롤 하이재킹 없이 가능한가 + SEO/접근성 영향

### 10-1. 하이재킹 없이 구현됨 (미리보기로 확인)
- 스크롤은 **브라우저 기본**이다. `wheel`/`touchmove` 리스너가 없고, 스크롤을 막는 `preventDefault`도 없다(코드에서 `preventDefault`는 Alt+방향키 이동, 탭 방향키, 막아 둔 미리보기 다운로드 링크 3곳뿐).
- 사용한 것: CSS `scroll-snap-type: y mandatory`(+ `scroll-snap-align: start`), `IntersectionObserver`(rootMargin `-50% 0 -50% 0`로 화면 중앙선에 걸린 화면 = 활성), `history.replaceState`, 앵커 `href="#id"`.
- 키보드 스크롤이 스냅과 맞게 동작함: PageDown 4회 → hero → index → start → download, Space → features, End → privacy, Home 복귀.
- 해시 이동·뒤로 가기·앞으로 가기·직접 링크 전부 PASS(미리보기에서 확인). 직접 링크에서 IO가 인트로를 먼저 알려 주소를 덮어쓰던 버그를 이번에 고쳤다(초기 600ms 잠금 + 즉시 이동).
- **한계 1(확인 필요):** `mandatory`는 스크롤이 끝나면 가장 가까운 화면으로 붙는다. 자동화 환경에서 휠 300px(화면 높이 800px의 37%)을 한 번에 주니 인트로로 되돌아갔다. 실제 마우스 휠·트랙패드에서 한 칸씩 자연스럽게 넘어가는지는 **실기기에서 확인하지 못했다.** 어색하면 `proximity`로 낮추는 선택지가 있다(결정 6번).
- **한계 2:** 화면이 뷰포트보다 키가 크면(낮은 창) `mandatory`가 아래쪽을 가릴 수 있어 높이 540px 이하는 스냅을 끈다.

### 10-2. SEO 영향
- 모든 카테고리 텍스트가 **DOM에 소스 순서대로** 있다(인트로 → 히어로 → 인덱스 → 6개 카테고리). h1은 인트로에 하나, 화면마다 h2, 창은 h3. 인덱스 노드는 실제 링크.
- 접힘은 높이 0 + `visibility:hidden`, 닫힘은 `hidden`이라 **노드는 항상 존재**(텍스트 길이로 확인). 다만 `display:none`/`visibility:hidden` 텍스트는 검색엔진이 가중치를 낮출 **가능성**이 있다 → 중요한 본문(기능·FAQ·다운로드)은 **기본 펼침**으로 두고 접기는 사용자 조작 때만 쓰는 것을 전제로 한다. 가중치 영향은 측정하지 못했다.
- 해시(`#faq`)는 별도 URL로 색인되지 않는다. **한 URL(`/`)에 모든 내용이 있는 구조**라 지금 랜딩과 같다. 정적 페이지(`about/faq/terms/privacy.html`)는 그대로 별도 URL로 남아 있다.
- 현재 랜딩처럼 클라이언트 렌더링(Vite SPA)이라 `<noscript>` 요약과 JS 렌더링 크롤러에 의존하는 점은 그대로다.
- 기존 SEO 메타·noindex(프리뷰)·`privacy.html`·`VITE_SITE_URL`은 건드리지 않는다(이번 작업은 설계와 미리보기뿐).
- Lighthouse SEO 점수는 미리보기가 `noindex`라 측정값(50)이 의미 없다. 실제 구현 후 프리뷰 배포가 아닌 운영 빌드 기준으로 비교해야 한다.

### 10-3. 접근성 영향
- 통과: 포커스 링 표시, Tab 순서(도구 모음 → 인트로 버튼 → …), Enter로 인덱스 노드 이동 후 제목 포커스, 창 키보드 조작(접기·닫기·열기·Alt+방향키), 입력창 단축키 무시, 움직임 줄이기, Lighthouse 접근성 100.
- 주의: ① 진행 표시 "03 / 06"에 `aria-live="polite"`를 달았는데 스크롤마다 읽혀 **수다스러울 수 있다**(제거 검토). ② 큰 글자·격자·노이즈·스파클·데모 화면은 `aria-hidden`. ③ **건너뛰기 링크**(본문으로)는 아직 없다. ④ 스크린리더 실제 낭독은 확인하지 못했다.
